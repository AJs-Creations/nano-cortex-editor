# Contributing

Thanks for helping. Bug reports, protocol findings and pull requests are all welcome.

## Workflow

- Branch from `staging` as `feature/<short-name>` (or `fix/<short-name>`).
- Open a pull request into `staging`. `staging` is merged into `main` for releases; releases are tagged `v*` on
  `main` and built by GitHub Actions.
- Keep commits focused, with a short imperative subject line.

## Before you open a PR

```bash
npm install
npm run test:ux
```

The UX test drives the editor on demo data with real mouse, wheel and key events and checks both what's on screen and
the exact Bluetooth packets each action sends. It must stay fully green; add checks for new behaviour. CI runs it on
every pull request as a required check. CI machines are slow, so wait on conditions (`waitFor`, `checkSoon`,
`txWait`, `settle` in the test) instead of adding fixed sleeps. Keep demo mode working: new pedal messages need a
demo answer too.

Don't edit `editor/index.html` (vendored upstream, verbatim) or `pro/core.js` (generated by `npm run build:core`).

If a change affects what users see, update `docs/MANUAL.md` and, where it helps, the screenshots
(`npm run docs:screenshots`, demo mode only).

## Hardware in the loop

The protocol is reverse-engineered. For anything protocol-related, verify on a real pedal: do the physical step, read
the Activity log (turn on **Developer tools** in Settings → General → Advanced, then ⌘L / Ctrl+L; it also enables
Record, protocol details and View → Classic Editor / Developer Tools), and describe what you saw in the PR. Don't guess byte formats. Back up your presets in
the official app before writing to a pedal, and never save without an explicit user action.

## Privacy: recordings are never committed

Session recordings (**Record**), PacketLogger / HCI traces (`.pklg`, `.btsnoop`, …) and capture bundles are never
committed, not even scrubbed. They carry serial numbers, Bluetooth addresses, account details and personal preset
names. `test/fixtures/sessions/` and these file types are git-ignored. When a test needs bytes from a recording,
inline the specific frame in the test (with any identifying values replaced), and in docs quote only short example
frames with nothing identifying in them.

## Branding

This is an unofficial project. Don't add Neural DSP logos, artwork or screenshots of the Cortex Cloud website, and
keep the trademark note in the README and the manual.
